## What to AVOID Next Time

### CRITICAL — Theme Push Rule
**NEVER use `shopify theme push --only="..."` from the parent `shopify customizations/` directory.**

This caused a ~2 hour debugging session where the homepage was stuck on 404. The partial `--only` push leaves remote section files in an inconsistent state — some files get deleted on the remote even though they exist locally.

**Always push from inside the theme directory:**
```
cd Dawn-Dev
shopify theme push --theme=Dawn-Dev
```

Or if pushing specific files only, do it from inside the theme directory too.

### Font Identifiers — Verify Before Pushing
Shopify font identifiers must match exactly what's in Shopify's font library. Format: `{font_name_underscored}_{style_char}{weight_digit}` e.g. `bebas_neue_n4`, `dm_sans_n4`.

If unsure whether a font exists in Shopify's library, set it via **Admin → Themes → Customize → Typography** first. Once saved via the admin, pull the theme and read `settings_data.json` to get the exact identifier Shopify wrote. Use that identifier in future pushes.

### Shopify GraphQL Auth
The `shopify store execute` CLI command requires stored auth for the store:
```
shopify store auth --store athlents.myshopify.com --scopes write_content,read_content
```
Auth is not set up for athlents.myshopify.com — any GraphQL page/product mutations must either set up auth first or be done manually in the admin.

### settings_data.json "Could Not Be Deleted" Error
When pushing `settings_data.json` alone with `--only`, Shopify sometimes throws:
```
Failed to delete config/settings_data.json: could not be deleted
```
The upload still succeeds (100%), the cleanup just can't delete it. This is a known Shopify quirk for protected files. Not a real error — settings ARE applied. But to be safe, always do a full push anyway.
